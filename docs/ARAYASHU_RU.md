# Arayashu Hard: настройка версии 3.5.6

Это отдельная экспериментальная сборка форка, основанная на upstream 3.5.5.

1. В версии из этой ветки открой Hard MD → Solo setup, выбери профиль и нажми Apply.
   Это применяет и сохраняет параметры бота; вручную повторять Graces, приоритеты
   и выбор десяти бойцов в интерфейсе бота не нужно. После подготовки игры нажми START.
2. Выбери Deep (410 Starlight со стартовой паутиной) или Economy (250).
3. Оставь Adversities: All для расчёта окупаемости ниже. None облегчает бой,
   но не даёт награды за Adversity Score.
4. Пресет выбирает одну команду POISE/SLASH, десять HoS, порядок
   Ryoshu, Sinclair, Don, Ishmael, Heathcliff, Faust, Outis, Rodion, Yi Sang, Hong Lu.
5. В игре выставь соответствующие HoS Identity и назови пресет POISE.
   LCB Meursault и G Corp. Gregor — на скамейке, вне развёртывания/резерва боя.
6. На старте нужны Cigarette Holder, Stone Tomb и только один Gift Search:
   Spiderweb Entangled in Red за 70. Наличие паутины проверь перед боем.
7. Первый запуск — один забег под наблюдением. Рёсю должна использовать защиту,
   казнить HoS и остаться одна; погибшие должны сохраняться мёртвыми.
8. Бот не продаёт подарки в Arayashu. При нераспознанной паутине слияние блокируется.
   Нехватка Cost в этом режиме может отложить покупки — это намеренная защита.
9. При ошибке распознавания или отсутствии прогресса казней бот останавливается.
   По умолчанию допускаются максимум две неудачные попытки MD за пакет запусков.
10. Не бери Record Logs of That Day: обработчик всех cursed-событий ещё не реализован.

## Бюджет без отдыха и случайных поступлений

| Очищенный этаж | Уже принятый Adversity Score | Доход | Deep 410 | Economy 250 |
|---|---:|---:|---:|---:|
| 10, выход до EXTREME | 0 | 260 | -150 | +10 |
| 11 | 9 | 420 | +10 | +170 |
| 12 | 20 | 610 | +200 | +360 |
| 13 | 33 | 830 | +420 | +580 |
| 14 | 46 | 1050 | +640 | +800 |
| 15 | 60 | 1285 | +875 | +1035 |

Расчёт относится к завершению с получением награды. Вход на этаж и поражение
не равны зачистке. Неудачные старты расходуют вложения заново.
При Adversities: None награды за очки ограничений нет.

Тесты имитируют игровой ввод. Они проверяют исправленные ветки логики,
но не доказывают прохождение 15-го этажа. Саму игру в CI запустить нельзя.

## Сборка на Windows, если GitHub Actions не запускает runner

Нужен Python 3.12 с Windows Python Launcher (команда py).
Из корня исходников запусти:

```powershell
.\build-arayashu-windows.ps1 -Target gui
```

Скрипт создаёт отдельное окружение venv-arayashu, запускает проверки,
устанавливает зависимости и собирает build/app.exe. Без -Target gui он
собирает также app_debug.exe. При ошибке проверки сборка не продолжается.
После компиляции проверяются версия бинарника и SHA-256.
Сборка не запускает игру и не подтверждает прохождение этажей.



## Диагностика качества забега

В Arayashu диагностический отчёт включается автоматически, независимо от кнопки LOG.
Дополнительно настраивать его в Solo setup не нужно. Для каждого нажатия START
создаётся отдельная папка (метка времени UTC и случайный идентификатор):

```text
%USERPROFILE%\ChargeGrinderLogs\arayashu\<дата_идентификатор>\
```

На Linux путь — `~/ChargeGrinderLogs/arayashu/`. Точный путь также выводится
в консоль и обычный game.log, если обычный лог включён.

- `summary.json` — сводка по каждой попытке: исход и причина остановки,
  продолжительность, этажи, бои, повторные попытки, подтверждённое одиночное
  состояние Рёсю, последнее распознавание паутины, Cost и счётчики событий.
- `events.jsonl` — последовательность событий с временем и номером попытки:
  настройки, экраны старта/продолжения, пакеты, защитные ходы, живые/мёртвые
  союзники на экране выбора, инвентарь, блокировка продажи, выбор ингредиентов,
  карты наград, отправленные ограничения, восстановления после ошибок и паузы.
- `*.png` — снимки игрового окна до/после выбора Graces, после входа, при первом
  защитном ходе, на экране награды/поражения или остановки. Не более шести снимков
  на попытку и двадцати на START; повторяющаяся контрольная точка снимается один раз.
  Снимок пропускается, если активное окно не принадлежит Limbus Company.

Строка `max_floor_estimate` может включать запасной счётчик этажа. В
`max_floor_confirmed` попадают только этажи, прочитанные шаблонами на экране.
`cleared_floor_lower_bound` выводится из подтверждённого перехода на следующий
этаж; при успешном завершении учитывается последний подтверждённый этаж.
Ошибка на 11-м этаже сама по себе не означает зачистку выше 10-го. Это всё ещё
результаты распознавания интерфейса, а не данные внутреннего API игры.

`last_alive` фиксируется на экране выбора бойцов, а не поминутно во время боя.
`last_spiderweb_recognized: null` означает, что проверенного сканирования ещё
не было; `false` — шаблон не найден, что само по себе не доказывает потерю гифта.
Cost записывается отдельно от Starlight, с исходным и пересчитанным балансом.
Время — полное время, включая паузы; события паузы позволяют учесть их при разборе.

**Starlight не выдаётся за измеренный доход.** `configured_entry_budget` — бюджет
из выбранных Graces плюс один поиск паутины за 70, а не подтверждённое списание.
`reference_projection` — только справочный расчёт из таблицы выше при успешном
новом старте с All Adversities и без бонуса/Wishmaking. Для продолженных,
неудачных забегов и режима None эта оценка не выводится. Она не проверяет реальные
очки ограничений, случайные награды и все списания; `actual_starlight_net`
остаётся `null`. Снимки Graces и экрана наград нужны для проверки реальных цифр.
Количество выбранных значков ограничений не считается прочитанным Adversity Score.

Для разбора пришли архив **всей папки одного START**, особенно если были неудачные
попытки перед успешной: один успешный забег не доказывает прибыль всей серии.
Файлы сохраняются только локально и автоматически никуда не отправляются.
Webhook-адреса и полные настройки приложения в отчёт не включаются.
JSON-сводка обновляется по ходу забега: при аварийном закрытии останется статус
`running` и последние записанные события. Ошибка записи диагностических файлов
отключает диагностику, не запускает новый забег и не меняет игровую логику.
